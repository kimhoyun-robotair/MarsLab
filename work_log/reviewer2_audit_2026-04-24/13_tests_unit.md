# Reviewer 2 Audit — tests/unit/ (60 files incl. conftest.py)

Hostile external review. Scope: the *test code* itself, not the production it exercises. Questions throughout: "would this catch a regression?", "could values silently change and the assertion still pass?", "is the oracle file-identity or behavior?"

Files examined: all 59 test files + conftest.py under `tests/unit/`.

## CRITICAL — tests that claim to catch a regression but would not

### C1. `test_monolithic_new_uses_main_loop.py:50-64` — Oracle "md5 unchanged" is a file-identity test, not behavior

Quote:
```python
def test_oracle_md5_unchanged() -> None:
    ...
    digest = hashlib.md5(ORACLE_PATH.read_bytes()).hexdigest()
    assert (
        digest == "beefa12579dd43f3da27b1dae3c6f852"
    ), f"Oracle md5 drifted to {digest}; run_stage3_monolithic.py is frozen."
```

**Problem.** The reviewer brief explicitly names this pattern. This hash proves only that the bytes of `run_stage3_monolithic.py` are unchanged — it does not execute the oracle nor compare its outputs against anything. A reformat, whitespace change, or comment edit breaks the test; a functional regression (e.g. the oracle imports a module that itself changed semantics) does not. Worse, the same md5 is duplicated in `test_monolithic_new_seed_propagation.py:159`, so any oracle edit requires editing *two* magic strings. This is "comment-as-deodorant smell" — the test name claims behavioral guarantee; the body verifies only identity.

**Fix.** Either (a) replace with an offline "oracle run produced these outputs" regression (seeded tiny config → hashed numeric arrays) or (b) delete both md5 guards and rely on git history for the "do not edit this file" social contract. The current form is CI-theater.

### C2. `test_cave_generator.py:365-388` — `_R5_REGRESSION_HASH` lumps 8 heterogeneous buffers into one sha256, and float64 casts hide float32 drift

Quote:
```python
_R5_REGRESSION_HASH = "047936be6a2ffb03adb38e1665eac58e3c721285c144fe79b3282f9b7a7b5840"

def test_r5_regression_hash_stable():
    ...
    bd = [(b["x"], b["y"], b["z"], b["diameter"]) for b in result["breakdown_positions"]]
    parts.append(np.asarray(bd, dtype=np.float64).tobytes())
    ...
    parts.append(np.nan_to_num(result["surface_elevation"], nan=-9999.0).tobytes())
```

**Problem.** Three independent risks:

1. `np.asarray(..., dtype=np.float64)` converts Python floats that might have started as float32 — a float32 precision regression in `breakdown_positions` gets silently upcast and hashed-identical.
2. `nan_to_num(..., nan=-9999.0)` stamps a hard-coded sentinel over every NaN in `surface_elevation`; if the generator regresses to emit *different* NaN patterns, the sentinel squashes the signal.
3. One monolithic sha256 means any drift gives a single uninformative failure ("bit-exact regression guard failed") with zero diagnostic information. You cannot tell from CI which of {tube, floor, surface, skylights, debris, breakdown, skylight_positions, surface_elevation} drifted.

**Fix.** Per-component hashes stored in a dict-shaped golden file; fail with the component name and diff. Remove the float64 cast; preserve float32. Remove `nan_to_num`; hash the NaN mask separately.

### C3. `test_monolithic_new_seed_propagation.py:144-166` — `test_oracle_still_unmodified` silently passes when the oracle is missing

Quote:
```python
def test_oracle_still_unmodified():
    oracle_path = REPO_ROOT / "scripts" / "phase1" / "run_stage3_monolithic.py"
    if not oracle_path.is_file():
        return
```

**Problem.** `return` instead of `pytest.skip`, and no `pytest.fail`. If someone deletes or renames the oracle — the exact regression the test exists to catch — this test passes silently. A CI green tick should never be producible by erasing the subject-under-test.

**Fix.** `assert oracle_path.is_file(), "Oracle vanished — this test requires it present"`. Then skip-or-fail semantics are explicit.

### C4. `test_cave_generator.py:95-103, 106-113` — dimensional tolerance so wide the test is a shape check in disguise

Quote:
```python
def test_tube_bounding_box_width(cave_full):
    ...
    assert x_range > configured_width * 0.5
    assert x_range < configured_width * 2.0
```

**Problem.** `[0.5w, 2w]` is a factor-of-4 window. A tube whose width regresses from 200 m to 110 m (a 45% geometric error) still passes. Same for `test_tube_height` — `[0.5h, 2h]`. The test name implies "width is approximately configured"; the body accepts any value within a factor of two. This is the textbook shape-check-masquerading-as-behavior smell.

**Fix.** Tighten to ±10-15% on the mean, not max-min (the max-min captures noise amplitude, not width). Better: assert on the centerline-perpendicular width statistic, not the AABB.

### C5. `test_terrain_loader.py:36-72` — cave branch test stubs the generator, so nothing is verified

Quote:
```python
def test_load_scenario_terrain_cave_branch(monkeypatch: pytest.MonkeyPatch) -> None:
    ...
    def fake_generate_cave_mesh(**_kwargs: object) -> dict:
        return fake_cave
    monkeypatch.setattr(
        "marslab.terrain.cave_generator.generate_cave_mesh",
        fake_generate_cave_mesh,

    ...
```

**Problem.** The stub returns whatever the test constructed; the assertion verifies that what the stub returned came back out. This checks plumbing-of-the-stub, not plumbing-of-production. A future refactor that forgets to call `generate_cave_mesh` entirely but constructs its own return dict still passes. No `mock_fn.assert_called_once_with(...)` to verify the real function was invoked.

**Fix.** At minimum `mock.assert_called_once()` with kwargs matching the cfg. Better: track calls and verify the fake receives the right `seed`, `tube_width_m`, etc.

### C6. `test_seed_reproducibility.py:79-85` — "different seeds differ" doesn't assert the full pipeline actually differs

Quote:
```python
def test_different_master_seeds_differ():
    r1 = _run_pipeline(master_seed=42)
    r2 = _run_pipeline(master_seed=99)
    assert not np.array_equal(r1["elevation"], r2["elevation"])
    assert r1["rock_positions"] != r2["rock_positions"]
```

**Problem.** Only `elevation` and `rock_positions` are compared. `sun_zenith`, `intensity`, `diffuse`, and `sky_rgb` are in `_run_pipeline`'s return but not asserted because they depend on atmospheric config, not seed. Fine — but this means the test does not exercise the seed-propagation claim across the *full* pipeline. If seed stopped propagating to terrain (say, terrain switched to a module-level RNG), rocks would still differ because they're seeded from `terrain.seed`. The test passes with a half-broken propagator.

**Fix.** Also test that fixing master seed and varying *no other state* gives identical elevation for two consecutive propagator calls, and that the propagation formula `terrain.seed == mars_env.seed + 1` is exercised explicitly (the covering test in `test_seed_propagation_offsets` only checks +1 offset, not that *all* fields are actually derived from master).

## HIGH — weak assertion patterns

### H1. `test_cave_breakdown.py:42-63` — coverage test has vacuous floor

Quote:
```python
placed_area = sum(np.pi * (b["diameter"] / 2.0) ** 2 for b in blocks)
...
assert placed_area > 0.0
assert len(blocks) > 10
```

**Problem.** `coverage_pct=20` requested; test asserts `len(blocks) > 10`. The comment says "we just check that the loop actually ran for a sensible number of blocks" — i.e. the author explicitly decided not to assert on the actual coverage. A regression cutting coverage from 20% to 0.5% still passes as long as ≥11 blocks exist.

**Fix.** Assert `placed_area / tube_area ∈ [0.10, 0.25]` — a real bound around the requested 20%.

### H2. `test_cave_features.py:96-100` — debris cone base radius ±25% on a ~5% claim

Quote:
```python
    # +/- 25% slack for the 5% gaussian noise applied per vertex.
    assert (0.75 * expected_base) <= radii.mean() <= (1.25 * expected_base)
```

**Problem.** The comment acknowledges noise is 5% per vertex, but the mean of N=24 samples should converge within ~1%, not 25%. A regression that halved the base radius fits inside 25% slack only if the bug is >50%, which is backward. The 25% bound is wishful tolerance.

**Fix.** `abs(radii.mean() - expected_base) / expected_base < 0.05`.

### H3. `test_mesh_builder.py:80-93` — `test_source_text_winding_guard` reads Python source

Quote:
```python
def test_source_text_winding_guard():
    source = inspect.getsource(compute_mesh_arrays)
    assert "i00" in source
    assert "i01" in source
    assert "i10" in source
    assert "Triangle 1: i00, i01, i10" in source or "face_indices[0::6] = i00" in source
```

**Problem.** Tests the variable names in the source, not the behavior. A legitimate refactor renames `i00` to `row_col_00` and the test fails; a bug-for-bug rewrite that keeps the names passes. This is regex-on-source masquerading as correctness verification. `test_all_face_normals_positive_z_flat` above it is the real test.

**Fix.** Delete. The three positive-Z normal tests (`_flat`, `_slope`, `_noisy`) cover the invariant correctly.

### H4. `test_odometry_math.py:62-63` — non-commutative assertion uses `np.allclose(..., atol=1e-4)`

Quote:
```python
assert not np.allclose(a, b, atol=1e-4)
```

**Problem.** `assert not np.allclose(...)` is a "something changed at all" test — the bar is that two quaternions differ by more than 1e-4. Any bug that made quaternion multiply nearly commutative but not exactly (e.g. returned `q1*q2 + 1e-3*(q2*q1 - q1*q2)`) would still pass. A property-based test generating random unit quaternions and checking `|q1*q2 - q2*q1| > some_threshold_based_on_angle` would be tighter.

**Fix.** Assert magnitude of the commutator, not just non-equality.

### H5. `test_config_schema.py` — legion of "does field equal the default" tests

Examples: `test_mars_env_defaults` (L27), `test_dynamic_atmosphere_config_defaults` (L406-416), `test_tau_constant_config_defaults` (L463-466), `test_tau_ramp_config_defaults` (L475-479), plus every `*_defaults` in `test_atmosphere_schema.py`.

**Problem.** A default-value assertion just mirrors the schema source. If someone changes the default in the schema, tests fail mechanically — they do not verify the default is *sensible*. The test catches typos in numeric literals at test-edit time but provides no defense against semantic regression. Treat these as schema-echo tests, not behavior tests.

**Fix.** Collapse to one or two "values load and round-trip through YAML" tests. Move actual semantic checks (is 3.72 m/s² Mars gravity?) into `test_mars_env_schema.py::TestDefaultGravity::test_default_gravity_exactly_3_72` which does lock the number — keep that, delete the rest.

### H6. `test_atmosphere_schema.py:170-177` — immutability test via model_copy doesn't test immutability

Quote:
```python
class TestImmutability:
    def test_model_copy_is_independent(self) -> None:
        base = DynamicAtmosphereConfig(time_scale=200.0)
```

### H7. `test_drive_api_setup.py` — entire suite uses homegrown `_FakeStage`/`_FakePrim`/`_FakeDriveAPI`

Quote (L140-171):
```python
ok = _apply_drive_api(
    stage, joint_path, stiffness=0.0, damping=1000.0, max_force=500000.0,
    drive_type="acceleration",
)
assert ok is True
prim = stage.GetPrimAtPath(joint_path)
assert prim.attrs["drive:angular:physics:stiffness"] == pytest.approx(0.0)
```

**Problem.** The fake's `CreateAttribute` returns `_FakeAttr(self, name)`, which stores `None` in `prim.attrs[name]`; `.Set(value)` then writes the value back. The test writes and reads the same dict. A regression where `_apply_drive_api` writes to `drive:linear:physics:stiffness` instead of `drive:angular:physics:stiffness` would pass: the fake treats any key as a literal string, so the lookup against `"drive:angular:..."` fails and the test errors out only if production is *perfectly* correct — but the test author controls the key string they assert, so whatever production *actually writes* is what passes. The tests are self-consistent but verify no USD behavior. The `applied_paths` list is populated but never asserted. `IsValid()` always returns True — the "prim not valid" code path is untested.

**Fix.** Add negative-path tests (prim is invalid → function returns False). Assert the exact set of keys written matches the expected USD attribute name list so that typos like `physics:stifness` fail.

**Problem.** Any *other* test earlier in the session (e.g. `test_sensor_spawner.py`) that monkeypatches `pxr` into `sys.modules` will still leave it there across tests (fixture scope is per-test for monkeypatch, so it should be cleaned — but if any test installs `pxr` at session scope, this assertion erroneously fails *or* erroneously passes depending on test order). Fragile to test ordering.

**Fix.** Run in a subprocess with a clean sys.modules.

### M12. `test_ros2_bridge_lazy_import.py:10-15` — `_prune` mutates `sys.modules`

Quote:
```python

    for key in list(sys.modules):
        for m in modnames:
            if key == m or key.startswith(m + "."):
                sys.modules.pop(key, None)
```

**Problem.** Tests mutate global state and never restore it. If a later test expects `rclpy` to be imported (there isn't one right now, but the invariant is implicit), it could break. `pytest` sees no fixture teardown.

**Fix.** Use `monkeypatch` or a fixture that snapshots `sys.modules`.

### M13. `test_cave_generator.py:165-171` — skylight depth "at least 30m" magic number


**Problem.** Magic number 30 with no cross-reference to the SMALL config. For `SMALL`, surface_z=150 and floor_z=0 → expected depth is 50m of ceiling thickness; 30 is a soft floor. Drift to 31m and the test passes despite a 40% regression.

### M14. `test_main_loop_structure.py:107-134` — `test_atmosphere_state_defaults` couples to schema defaults

**Problem.** The test sources the expected value from the schema and then asserts the loop state copied them verbatim. That's not a regression guard — that's a tautology modulo the dataclass wiring.

### M15. `test_odometry_publisher.py:190-219` — monotonic stamp test

## 3-line summary

The suite is large (59 files) and has strong quaternion/mesh-winding/Ackermann invariant tests alongside a dangerous layer of pseudo-regression tests: md5-file-identity oracles (C1, D1, D2), `sha256` of concatenated heterogeneous buffers (C2, D3), string-grep-on-source assertions masquerading as delegation proofs (C5, D2, M1), and factor-of-2-to-4 tolerance windows that name themselves after tight claims (C4, H1, H2, H18, L2). The "seed determinism" tests mostly check `e1 == e2` via equal inputs rather than compare against a golden hash (C6, H4 negative-style). No property-based tests (Hypothesis) exist anywhere; scientific-accuracy tests re-derive the formula they're validating and call the result "within 5% of published" (H12, L7). Recommend: (a) collapse the 18 redundant default-echo tests into one YAML round-trip, (b) delete the two md5 file-identity guards and the monolithic sha256 in favour of per-component golden outputs with diagnostic diffs, (c) replace `>/<` tolerances that span more than ±20% with tight bounds sourced from cited references, and (d) introduce Hypothesis for quaternion algebra and Ackermann geometry invariants.
